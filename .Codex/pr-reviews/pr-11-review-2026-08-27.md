## Important

### Functional

1. **`n_predict` bypasses the exact context reservation** -
   `src/gateway/request.rs:97-118`, `src/gateway/fabric/local_pool/mod.rs:263-307`.
   `output_token_budget` reads only `max_completion_tokens` and `max_tokens`,
   but the schema-preserving body forwards everything else, and llama.cpp
   honors `n_predict` over both aliases. A client sending `n_predict: 500000`
   is budgeted at the pool default (16k) while llama.cpp attempts 500k: the
   input + output + reserve guarantee is void, and the request fails or
   context-shifts mid-stream after commitment. Fix: treat a present non-null
   `n_predict` as an output-budget source, or reject it as `incompatible` for
   local admission.

2. **Token-count 4xx misclassified as member incapability** -
   `src/gateway/fabric/local_pool/member.rs:160-167`. Every non-success from
   `/v1/chat/completions/input_tokens` becomes `Unsupported` -> `Unhealthy`.
   The endpoint applies the chat template, so a request-caused 400 (template
   rejection, oversized prompt) is deterministic across all members yet is
   retried against each, logged as member failure, reported 503 pool-unhealthy,
   and on `cloud_allowed` routes spills the prompt to a provider. Fix: map
   4xx to a request-level rejection (400 or `incompatible`); reserve
   `Unsupported` for 404/501 and unparseable bodies.

3. **Post-admission local fall-forward never records
   `octoroute_fabric_pool_fallbacks_total`** -
   `src/gateway/fabric/service/routing.rs:131-160`. The local 5xx and
   transport-error arms return `FallForward` without the metric the contract
   names as "the signal that local capacity is spilling to cloud". The
   crashy-member scenario (admitted, then 500s or hangs pre-commit) is
   invisible while the provider side of the same event is counted, so the
   spill is misattributed to the provider alone. Fix: record
   `PrecommitFailure` in both arms, mirroring the provider path.

4. **Dispatch-time provider 401/403 commits to the client and can never fall
   forward** - `src/gateway/fabric/service/routing.rs:235-290`. Only 429 and
   5xx response arms fall forward. A route that explicitly lists
   `unauthenticated` in `fallback_on` gets it honored at admission (credential
   resolution) but not at dispatch (credential rejection), which are the same
   operator condition. The client also receives the upstream's raw 401, which
   reads as its own gateway credential failing. Fix: add a 401/403 arm gated
   on `may_fall_forward(Unauthenticated)`, calling `record_dispatch_failure`
   and falling forward when configured; if the asymmetry is deliberate, the
   trigger is narrower than its name and `provider_state_error`'s wording
   suggest, so document the scope.

5. **Codex readiness collapses auth misconfiguration into `Unavailable`** -
   `src/gateway/fabric/provider/mod.rs:516-527`. Every `codex::probe` error,
   including `NotChatGpt` (CLI authenticated with an API key instead of the
   ChatGPT subscription), maps to `Unavailable` -> `FallbackTrigger::Unhealthy`,
   which is in the default fallback set. The design's stated reason
   `unauthenticated` is excluded from defaults ("an expired key is an operator
   error, and silently rerouting the traffic and the spend it carries hides
   it") applies equally here, yet a wrong-auth-mode Codex provider silently
   spills every request to the next step. Fix: map `NotChatGpt` (and arguably
   `Diagnostic`) to `Unauthenticated`.

6. **Duplicate-target config error interpolates raw, unvalidated config text** -
   `src/gateway/fabric/config/validation/targets.rs:201-209`. The duplicate
   check runs on the raw step string before `RouteTarget::from_str` and formats
   it into the error; `from_str` carries an explicit comment that this field's
   raw text must never enter an error message. A step containing a planted
   secret or newline lands on stderr. Fix: parse steps first (FromStr never
   echoes), then duplicate-check parsed targets. This also fixes the ordering
   quirk where `["provider:nope", "provider:nope"]` reports "duplicate target"
   instead of "unknown provider".

7. **Anthropic fail-closed enforcement stops at the top level** -
   `src/gateway/fabric/anthropic/request.rs:120-123, 188-313`. Unknown nested
   keys are silently dropped: `reasoning: {"enabled": true}` (a documented
   OpenRouter form) produces a non-thinking request, dropping the caller's
   reasoning control; `function.strict` is dropped, weakening the tool
   contract; message/content-block fields (`cache_control`, `citations`,
   `name`) vanish. The contract's stated rationale for the top-level allowlist
   ("a caller gets a plausible answer to a request that was quietly altered")
   applies at these levels too. Fix: reject unknown keys in message objects,
   content blocks, tool/function objects, and the `reasoning` object.

8. **Doc/code disagreement on admission order and its false-Busy cost** -
   `docs/configuration.md:64-70` vs
   `src/gateway/fabric/local_pool/mod.rs:276-299`. The doc lists probes before
   permit acquisition; the code acquires the member permit first and holds it
   across health/slot probes (up to 2s) and token counting (default 15s, max
   120s). With the shipped `max_in_flight = 1`, a second request during that
   window is reported `Busy` and on default `fallback_on` spills to cloud spend
   while the member is healthy and idle. The order is defensible (it closes
   the slot-check TOCTOU for Octoroute's own load), but the doc describes the
   opposite design and neither comments the false-Busy consequence. Fix one
   side or the other.

9. **`docs/configuration.md` misdocuments the fallback set in a
   safety-relevant way** - lines 229-231 list six triggers, omit
   `unauthenticated`, and say omitting `fallback_on` "enables the full closed
   set". The closed set has seven; the default deliberately excludes
   `unauthenticated` (`validation/mod.rs:299-304` explains why). The doc tells
   operators the default includes the one trigger the design says must never
   be default-on, and `unauthenticated` appears nowhere in `docs/` as a
   selectable value despite being supported and tested.

### Test gaps on contract invariants

10. **`reject_redirect` has zero coverage** - `transport.rs:480-489`. The
    redirect-refusal invariant (Anthropic 3xx leaking `x-api-key` cross-origin)
    has a documented attack story and no test; deleting the check passes the
    suite. Fix: wiremock a 302 from provider and local steps; assert
    pre-commit failure, no followed request, fall-forward per `fallback_on`.

11. **Local dispatch fall-forward untested** - `routing.rs:132-160`. All local
    tests cover admission-time rejection; none cover a member that admits then
    500s or hangs past `first_byte_timeout_ms`. Deleting the 5xx arm passes
    the suite. This gap is why finding 3 survived.

12. **Preflight surface untested** - `service/mod.rs:205-230`. Auth-before-body
    ordering, 431/413/429-with-Retry-After/concurrency-exhaustion each lack a
    discriminating test; reordering five lines in `handle_http_chat` passes.

13. **No post-commit target-switch regression test** - nothing pins "never
    switch target after the first client-visible byte" against a refactor: a
    mock that sends one SSE chunk then terminates without `[DONE]`, asserting
    headers still name the first target and no second upstream is contacted.

14. **Credential cache invalidation on 401/403 untested** -
    `provider/mod.rs:377-385, 417-420`. A two-env-value `TestEnvironment`
    (stale then rotated key) would pin re-resolution after a 401.

15. **Readiness snapshot cache (`cached_readiness`) untested** -
    `service/mod.rs:258-274`. The anonymous-amplification guard and its mutex
    discipline have no test; existing tests exercise only the provider-level
    TTL.

16. **Metadata endpoint authorization untested end-to-end** - `http.rs`. The
    bearer/anonymous split across `/v1/models`, `/metrics`, `/health/*` could
    invert with only two integration tests noticing nothing.

17. **`config_version` check and the "neither credential source" arm untested** -
    `validation/mod.rs:206-208`, `targets.rs:86-93`. Both are headline
    invariants with surviving-mutant exposure under the repo's own
    cargo-mutants gate, along with a broader set of structural validators
    (duplicate names, unknown cross-references, config-level privacy rules,
    timeout bounds, default fallback-set contents) that have no fixtures.

18. **Flaky by construction: process-global metric counter race** -
    `metrics.rs:427-435` (`each_adapter_counts_separately`) reads a
    process-static counter, records once, asserts `before + 1`, while
    `anthropic/tests.rs` records the same counter from parallel threads. Any
    interleaved record fails the assertion nondeterministically.

19. **Codex process-level failure paths untested** - timeout kill,
    `OutputTooLarge`, non-zero exit, missing executable, `turn.failed` mid-run,
    and the doctor-probe failure modes all lack fixtures despite the module's
    contract promising bounded capture and a killing timeout.

20. **"Never forward inbound Authorization upstream" lacks a discriminating
    assertion** - wiremock `header(name, value)` matchers assert presence of
    the correct credential, not absence of the inbound one; a regression
    forwarding both passes.

## Minor

Routing/service:

- `NoEligibleTarget` maps to 503 with error type `invalid_request_error`
  (`responses.rs:86-100`): the status says retry, the type says malformed
  request; clients keying on `error.type` do the wrong thing.
- Terminal errors report only the last step's state (`tests/gateway_v3.rs:176-184`
  shows `workers` busy reported as `local_pool_disabled` from the next pool);
  the actionable rejection is only in logs.
- Local upstream 429 is never classified `rate_limited` (`routing.rs:132-134`);
  the provider path honors the trigger, the local path doesn't.
- Adapter/translation failures commit 400 `provider_request_invalid`
  (`routing.rs:197-205`): gateway-side faults labeled as client errors, with
  no metric.
- 429 fall-forward doesn't invalidate cached provider readiness while 5xx does
  (`routing.rs:236-274`); the asymmetry is uncommented.
- `routing_duration_seconds` records only admitted steps; rejected steps do the
  same probe work, so the histogram goes quiet exactly during outages.

Local pool:

- Unbounded `.json()` reads on upstream-controlled probe bodies
  (`member.rs:117, 142, 169`) against the repo's bounded-everything posture.
- Deterministic overflow (`output + safety >= context_window`) still burns a
  token-count probe before rejection (`mod.rs:300-307`).
- Runtime URL resolution assumes the validator ran; `base.join(path)` drops the
  last segment without a trailing slash and `LocalPoolConfig` fields are `pub`
  (`mod.rs:457-461`).
- `include_reasoning` counts as a capability for gating (`request.rs:209`) but
  not as a caller control (`request.rs:142`), so it attracts the pool default
  `reasoning_effort` alongside.
- Pool default reasoning injection ignores the pool's capability declaration:
  `default_reasoning_effort` is mandatory and injected even when the pool
  doesn't declare `reasoning`.
- No test that the permit lives through the response body and is released on
  drop or on rejection.
- Several mutation-sensitive gaps: fresh-cached-health branch, `used_context ==
  context_window` boundary, `degraded_state` precedence, slot-503 -> `Busy`.
- The "unhealthy member skipped before disclosing" test doesn't discriminate
  disclosure (no `expect(0)` on the unhealthy member's `input_tokens`).

Transport/HTTP:

- Codex dispatch discards its error chain (`transport.rs:149-151`): the routing
  log shows only a static message; every other variant carries `#[source]`.
- `read_bounded` mislabels mid-body failures as `ReadFirstChunk`
  (`transport.rs:372-375`).
- `first_byte_timeout_ms` bounds the full translated-body read on non-stream
  Anthropic (`transport.rs:207-211`), wider than the documented "hung upstream
  until first byte" semantics.
- Rate limiter is a process-global fixed window (`http_support.rs:70-111`):
  one client at the cap starves all; 2x burst at window boundary. Undocumented.
- Any `to_bytes` failure becomes 413 (`service/mod.rs:211-224`), including
  client disconnects.
- Hardcoded `provider_runtime: "complete"` in readiness (`http.rs:142-145`).
- `LlamaCppPool::new` is a public constructor that builds its own client
  (`local_pool/mod.rs:176-182`), against the one-pooled-client invariant;
  only tests call it. `#[cfg(test)]`-gate it.

Anthropic adapter:

- Sampling values forwarded with only an `is_number` check
  (`request.rs:472-484`): `temperature: 1.5`, `top_k: 3.5`, negatives become a
  committed upstream 400 instead of `incompatible`.
- `tool_choice` without `tools` silently dropped; `tools: []` forwarded
  (`request.rs:330-402`); both checkable at translation time.
- Empty text blocks and empty content arrays forwarded to Anthropic for a
  committed 400 (`request.rs:284-305`).
- Events after `message_stop` are still translated and emitted after
  `data: [DONE]` (`response.rs:189-203`).
- Partial usage reports a zero half; cache tokens dropped
  (`response.rs:479-491`).
- First-message-must-be-`user` unchecked (`request.rs`); becomes a committed
  upstream 400 instead of `incompatible`.
- tool_call `type` never verified (`request.rs:210-246`).
- `fragmented_anthropic_sse_is_incrementally_translated` never fragments
  (`tests.rs:326-344`): every `push` is one complete event, so reassembly
  regressions pass.
- Streaming usage merge, truncated-stream rejection in `finish()`, config
  `reasoning_effort` fallback, and a list of smaller translation arms are
  untested; the main translation test asserts block types but not parsed
  `input` objects.

Codex/provider:

- Any event after `turn.completed` fails the run as `Contract`
  (`codex/events.rs:30-32`): the skip-unknown policy exists for forward
  compatibility, but a trailing event from a future CLI hits this cliff.
- Early `turn.completed` is mislabeled as an unknown upstream type
  (`events.rs:51-58`), polluting the unknown-types metric.
- Present-but-empty usage reports zeros instead of omitting the key
  (`events.rs:85-91`), the trap the Anthropic contract explicitly avoids.
- `run_process` timeout is unreachable on the `execute` path
  (`codex/mod.rs:144-165` vs `transport.rs:165-167`): the outer timeout always
  fires first, so the graceful `stop()` only ever serves `probe()`. Safe, but
  redundant and uncommented.
- Credential-command worst-case wait is 2x the documented bound
  (`credential.rs:124-146`): 5s for stdout read plus 5s for `wait`, holding
  the credential mutex.
- Anthropic admission deep-clones the body twice (`provider/mod.rs:317-329`).
- Protocol-auth mapping duplicated between probe and dispatch
  (`provider/mod.rs:537-548` vs `transport.rs:182-187`), including a second
  `ANTHROPIC_VERSION` constant.
- `first_byte_timeout_ms` accepted for `codex_cli` providers but never applied.
- Mislabeled test: `event_contract_rejects_internal_tool_activity` passes even
  if `command_execution` handling is deleted; the asserted error comes from an
  invalid reply payload, not the tool item.
- The streaming test doesn't assert the single-chunk contract (count `data:`
  occurrences).
- `insert_header`'s `.expect` (`http_support.rs:184-189`) is unreachable only
  by validator discipline; a future looser validator turns it into a
  request-path panic.

Config:

- `validate_env_name` has no length bound (`fields.rs:140-152`): a 100KB name
  validates and is later interpolated into runtime errors.
- IPv4 link-local (169.254/16) trusted, IPv6 link-local (fe80::/10) not
  (`fields.rs:63-67`): same address class, opposite verdicts.
- `config.laptop.toml` is parsed by no test; only `config.toml` is pinned.
- Member address-class rule (loopback/private/.local) absent from
  `docs/configuration.md`; operators meet it only as a startup error.
- Two `config_with_first` anchors (`config/tests.rs:278, 282`) are not unique
  in the file; earlier insertion of the same line silently retargets the
  fixture.
- Empty `.env` values aren't filtered (`gateway/env.rs:67-72`) the way process
  env values are: `KEY=` yields `Invalid` instead of `Missing`.
- CHANGELOG entry sits under `[Unreleased]` while Cargo.toml ships 3.0.0.
- Codex service test uses Unix-only APIs without a `#[cfg(unix)]` gate
  (`service_tests/codex.rs:58`).

## Speculative

- Upstream can claim `x-request-id` on committed responses
  (`transport.rs:496` + `responses.rs:226-228`): the gateway then declines to
  set its own; `x-octoroute-request-id` remains authoritative, so impact is
  correlation confusion.
- `.env` duplicate keys are first-wins (`env.rs:130-134`); dotenvy convention
  is later-wins.
- Slot-check TOCTOU remains for non-Octoroute clients of the same llama.cpp
  server; over-admission degrades to a queued request bounded by
  `first_byte_timeout_ms`. Worth a sentence in the configuration doc.
- Member `priority` never overrides load (`local_pool/mod.rs:409-415`);
  operators may read it as preference. Doc point.
- A 404 from `/models` reports `Unavailable` though it proves reachability
  (`provider/mod.rs:412-426`); will mark healthy minimal providers down.
- Route-default reasoning effort reaches Codex without explicit provider
  configuration (`codex/mod.rs:115`), diverging from the "only explicitly
  configured providers" rule; looks intentional, deserves a comment.
- SSE event kind read only from the JSON `type` field, never the `event:` line
  (`anthropic/response.rs:219-222`): fine for Anthropic, invisible strictness
  for third-party compatible endpoints.
- `line_column` slicing could panic on a mid-char toml span
  (`validation/fields.rs:224-231`); no bad span producible, cheap guard
  available.
- CGNAT (100.64/10, e.g. Tailscale) members rejected per contract; will
  surprise mesh-network operators. Doc note.
- Health-cache TTL (1s) and credential-cache TTL (5min) are real-time constants
  with no clock injection, so expiry behavior is untestable as written.

## Strengths

- The privacy boundary is enforced by plan construction, not executor
  discipline, and the `TestEnvironment.reads()` audit proves provider
  credentials are never resolved on local-only requests. Hard to fake.
- `StepOutcome::Committed | FallForward` makes every non-committed path
  explicit at the executor level.
- Serialize-once is real: one `Bytes` buffer feeds both token counting and
  dispatch, pinned byte-for-byte by `body_json` matchers.
- The llama.cpp wire contracts (`/health`, `/slots?fail_on_no_slot=1`,
  `/input_tokens`) were verified against current upstream and match exactly.
- Anthropic adapter: zero panics and zero numeric casts on upstream-controlled
  data; the thinking-budget math is tested at its boundaries; the mixed-
  terminator test documents why it discriminates.
- Codex child lifecycle: every exit path reaps; argv/environment tests were
  written to catch flag deletion.
- The provider fallback matrix test and the closed-trigger-set table genuinely
  discriminate.
- `mutants-run.sh` decides on `missed.txt`, not the exit code, with the
  exit-3-vs-exit-2 reasoning documented; scratch-cleanup handles the
  SIGKILL-stranded-copy case.

## Recommendation

**Request changes.** The code quality is high and the architecture delivers the
contract's structural guarantees, but the Important list contains real
functional defects (findings 1, 2, 5, 7), a stated-invariant violation
(finding 6), observability gaps on the exact signals the contract calls out
(finding 3), safety-relevant doc errors (findings 8, 9), and untested
invariants the repo's own mutation gate would flag (findings 10-20). CI is
also not green at head, and the mutation job's unbounded runtime needs a
decision before merge.

Suggested order:

1. Fix functional defects: findings 1, 2, 5, 7 (then 4, 6).
2. Add the missing invariant tests: 10-14, 17 (each is small; most are table
   rows or one wiremock fixture).
3. Fix the two docs/configuration.md errors (8, 9) and the CHANGELOG section.
4. Resolve the CI mutation-job scope and timeout; wait for green at head.
5. Work the Minor list; most are one-line fixes or comments.
